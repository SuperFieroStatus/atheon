# Deploying Atheon to Render

Atheon runs as **one always-on Node web service** on Render that serves both the API
and the built React app, with a small **persistent disk** holding the SQLite database.
This reuses the same Render account/pattern as the Superior Service FSM project.

- **Cost:** web "starter" (~$7/mo, always-on) + a 1 GB disk (~$0.25/mo). No separate database bill.
- **Nothing to fill in by hand** — `JWT_SECRET` is generated by Render on first deploy.

Everything is defined in [`render.yaml`](../render.yaml) (a Render *Blueprint*).

---

## Step 1 — Put the code on GitHub

Render's Blueprint deploys from a Git repo. Atheon is already a local git repo with an
initial commit; you just need to push it to GitHub.

Create an empty repo on github.com (e.g. `atheon`), then from the project folder:

```bash
git remote add origin https://github.com/<your-username>/atheon.git
git branch -M main
git push -u origin main
```

(Or, if you have the GitHub CLI: `gh repo create atheon --private --source=. --push`.)

## Step 2 — Create the service on Render

1. Go to the Render dashboard → **New** → **Blueprint**.
2. Connect the GitHub repo you just pushed.
3. Render reads `render.yaml` and shows one web service (`atheon`) + a 1 GB disk. Click **Apply**.
4. First build takes a few minutes (`npm ci` → build the React app → start).

That's it — there are **no secrets to enter**. When the deploy goes green, open the
service URL (`https://atheon-XXXX.onrender.com`) and you'll get the sign-up screen.

## Step 3 — Hand it to the pilot team

Share the URL. Each teammate signs up with their email + name and gets their own
Personal workspace. To collaborate, one person creates a workspace/project and shares it
(👤 icon) with the others, or builds a Group from the 👥 menu.

## How it works

- **Single origin:** in production the Express server serves the built client from
  `client/dist`, so the app and API share one URL. Login cookies are `httpOnly` +
  `secure` and "just work" with no CORS/cross-site setup.
- **Database:** SQLite file at `DATA_DIR=/var/data/atheon.db` on the persistent disk.
  It survives restarts and redeploys. Schema is created/migrated automatically on boot.
- **Health check:** Render pings `/api/health`.
- **Auto-deploy:** pushing to `main` triggers a new deploy automatically.

## Backups

The DB is a single file on the disk. To grab a copy, open the service's **Shell** in the
Render dashboard and run:

```bash
cp /var/data/atheon.db /var/data/atheon-backup-$(date +%F).db
```

…then download it, or (like the FSM project) add a small cron that copies it to
Backblaze B2. Not required for a pilot, but easy to add later.

## Troubleshooting

- **Build fails on the Node version:** `render.yaml` pins `NODE_VERSION` to `24.16.0`
  because Atheon uses Node's built-in `node:sqlite` (needs Node ≥ 24 to run unflagged).
  If Render says that exact version isn't available, set `NODE_VERSION` to the latest
  `24.x` it offers.
- **Data disappeared after a redeploy:** make sure the **disk** is attached (it's in the
  blueprint). Without a persistent disk, SQLite would reset each deploy.
- **Scaling:** the disk pins the service to a single instance — perfect for a pilot. If
  you later need multiple instances or heavier load, migrate to a managed Postgres
  (a separate, larger change).
